# 04-05 — Complete the embedded font for the characters text can use

## Why

Reported from real hardware 2026-09-04: the name `MOZZXL` renders with three
dots in place of the `X`, and the `V` in "CONNECTING TO SERVER" is a corrupt
glyph.

Both are the same cause, confirmed by dumping the embedded charset at `$4000`
against the screen codes `HOST_SCR` produces:

- `X` (screen code `$38`) is three isolated dots down the left edge — exactly
  the reported artefact.
- `V` (screen code `$36`) is a dense checkerboard.
- `F`, `J` and `Q` are likewise artwork rather than letters.
- `S`, `C`, `G`, `K` and the rest of A-Z and 0-9 are proper letters, which is
  why `WIZARD`, `ZOMBIE` and `MOZZ` have always looked right.

The five broken slots are precisely the letters the original game's own text
never used, so their glyph slots were reused for maze and sprite artwork. That
was safe when all text was compile-time constants. It stopped being safe when
player names became arbitrary user input.

## Shape

Draw letterforms for `F`, `J`, `Q`, `V`, `X` in the existing style (the font is
bolder and squarer than the ROM font — match it, do not paste ROM glyphs), and
move any artwork currently occupying those slots to codes outside the range
`HOST_SCR` can produce.

## Watch out for

- Check what actually uses those artwork glyphs before moving them. They are
  reachable from the maze, shot and wizard drawing paths, and a slot that looks
  like noise in a font dump may be a deliberate sprite tile.
- The prompt screen switches `CHBASE` to the ROM charset (`HOST_BOOT` writes
  `#$E0`) while the scoreboard uses the embedded font. Confirm which charset is
  active when each status message is drawn — the reported `V` corruption implies
  at least one message is drawn under the embedded font, so fixing the glyph may
  fix it, but the charset-selection path should be checked rather than assumed.
- The name field should reject or fold characters the font cannot represent
  rather than drawing garbage, as a backstop for anything missed.

## Done when

- A name using all of `F J Q V X` renders correctly on the scoreboard.
- "CONNECTING TO SERVER" renders correctly on hardware.
- `font_coverage_smoke.sh` fails if any screen code reachable from `HOST_SCR`
  maps to a glyph that is not the expected character.
