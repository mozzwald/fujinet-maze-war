# 04-02 — Give the local actor a render-only position

## Why

`LOCX/LOCY` is simultaneously the rendered position, the collision position and
the shot origin. There is no render-only state, so there is nothing to smooth
into — which is why every correction so far has had to be either a teleport or,
since `LOCAL_FOLLOW`, a walk that moves *gameplay* state one cell at a time.
The walk is a stopgap: it makes the correction look better by making the
simulation lie for several ticks. This plan replaces it with the real
separation.

## Shape

Add render X/Y alongside `LOCX/LOCY`. The simulation position is set
immediately from authority; the render position chases it. Draw and erase read
render state; collision, `NET_AHEAD_FREE`, shot origin and occupancy keep
reading simulation state.

## Watch out for

- The erase path is the trap. Every draw has a matching erase, and this phase
  has already produced three separate bugs from draw and erase disagreeing
  about which cells an actor occupies (`SETSUIT` sub-cell offset, the left/up
  shot spill, the `ERASHOT` mirror). Whatever the render position is, the erase
  must be driven by the same value that drew, not recomputed from simulation.
- `ERASMAN` blanks two characters at the actor's cell. With render and
  simulation positions differing, "the actor's cell" is ambiguous — pick one
  and make it explicit in the code, not implicit in which variable was handy.
- Retire `LOCAL_FOLLOW` in this plan rather than leaving both mechanisms live.

## Done when

- Corrections read as motion rather than a jump, judged by the user.
- The source guard passes: no gameplay decision site references render state.
- `NET_GLIDE_ON` and `LOCAL_FOLLOW` are gone, with their behaviour subsumed.
