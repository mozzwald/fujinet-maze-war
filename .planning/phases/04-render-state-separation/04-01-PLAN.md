# 04-01 — Lock the movement decision to the transmit tick

## Why

`NET_FRAME_DIV` (6 frames) and the cell period built from `MOVRATE` (also 6
frames) are the same rate but free-running in phase, and the phase
re-randomises on every stop, turn or block, because `PLRMVE` re-runs every
`MOVRATE` frames whenever `MOVEST` is 0. When they slip, one transmit window
contains two move decisions or none, so the client predicts a different number
of cells than the server runs. That is the residual correction source after
`b8d80d2`: roughly 3 corrections per 40s of scripted hard cornering, down from
about 11.

Making one event drive both removes the slip by construction rather than
reducing it.

## Shape

Set a "may start a cell" permission at the periodic transmit slot, and have the
local move decision consume it. The animation keeps running on `MOVRATE` for
smooth rendering; only the decision to begin a new cell is gated.

## Watch out for

- A cell currently takes 6 frames and the window is 6 frames — zero margin. If
  an animation overruns, the next decision arrives late and movement stutters
  instead of desynchronising. Shaving the cell (for example `MOVRATE` 1 for the
  later phases) buys slack but changes how the game feels, so it is the user's
  call, not a silent adjustment.
- Two earlier attempts at this coupling failed and are recorded in STATE.md:
  moving the *send* onto the movement clock starved the server (it transmits
  nothing during the four-phase animation), and publishing at the move
  *decision* fired up to 30 times a second while blocked or idle. This plan
  moves the *decision* onto the transmit clock, which is the remaining
  direction and the one that cannot starve the link.

## Done when

- The correction counters, measured with the existing 40s scripted cornering
  run, are materially below the current build on the same rig.
- Movement still feels right to the user on real hardware. This plan is
  `autonomous: false` for that reason: the metric can improve while the game
  feels worse, and only the user can judge the second half.
