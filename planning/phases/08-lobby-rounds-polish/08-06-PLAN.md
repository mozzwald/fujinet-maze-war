# 08-06 — Build configuration and reachable title/direct-connect UI

## Model and handoff

Use **`gpt-5.6-terra` with medium reasoning**. Validated build generation and reuse of the existing editor are bounded changes with direct checks.
Follow [08-MODELS.md](08-MODELS.md) for escalation, testing-based commit
approval, and handoff rules.

After required acceptance, recommend **08-07: `gpt-5.6-sol`, high
reasoning** for AppKey/SIO buffers and startup recovery. Include this in the
user-facing closing summary and saved summary, then pause for the user's model
switch. If a test/approval gate is pending, say the recommendation is conditional;
do not mark the step complete or begin the next step.

## Build changes

Add validated Make variables for `HOST`, `ROOM_PORT_BASE`, `ROOM_COUNT`,
`DEFAULT_PORT`, `LOBBY_BASE`, `MAZEWAR_APPKEY`, `KILL_LIMIT`, and build flavor
(LAN/QA/production). Generate a MADS include containing strings, byte constants,
and swapped port values. Changes to any variable must rebuild the Atari XEX.

Do not shell-substitute unescaped user values into assembler. Validate hostname,
URL length, numeric ranges, and appkey before generation.

## Atari UI

1. Replace the old unreachable title assets with a reachable 40-column title
   screen on `HOSTDISP/HOSTSCR`.
2. Show username, `FIRST TO n KILLS WINS`, RETURN to play, and OPTION for server
   setup.
3. Reuse the existing text editor around `HOST_FIELD`, `NAME_FIELD`,
   `TXT_INPUT`, and `TXT_DRAW`. Add a bounded numeric port editor rather than
   storing hand-edited low/high constants.
4. Direct Connect is runtime-only and accepts a host plus one port. It never
   writes the public Lobby selected-room AppKey.
5. Preserve the current connect/error diagnostics and make cancel return to the
   title without touching the active selection.
6. Treat a pre-connect kill-limit display as the configured default; the actual
   selected room's limit comes from its authoritative handshake/round state.
   Do not advertise a local default as a guarantee about another server.
7. Reuse 08-05's teardown/reset and menu-safe VBI for all setup/connect routes.
   Enforce the existing 31-character host and eight-character name capacities.

## Memory policy

Use reclaimed title data for static strings/tables and existing `HOSTBUF` and
`NAMEBUF` for editable values. Add only measured persistent state. No new
zero-page per-player data.

## Verification

- Byte-inspect two forced builds with different host/base/count/default values.
- Change each generated setting without forcing a rebuild and verify Make
  rebuilds the include/XEX; unchanged settings must not trigger needless builds.
- Emulator: RETURN default connect, OPTION edit/accept, OPTION cancel, invalid
  port rejection, unavailable host recovery.
- Physical Atari/FujiNet checkpoint for keyboard/console debounce and direct
  TCP connection.
