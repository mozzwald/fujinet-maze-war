# 08-05 — Voluntary leave and no-human grace

## Model and handoff

Use **`gpt-5.6-sol` with high reasoning**. Timed lifecycle transitions span reusable seats, departing sockets, firmware cleanup, and Atari state.
Follow [08-MODELS.md](08-MODELS.md) for escalation, testing-based commit
approval, and handoff rules.

After required acceptance, recommend **08-06: `gpt-5.6-terra`, medium
reasoning** for bounded configuration generation and existing setup UI reuse. Include this in the
user-facing closing summary and saved summary, then pause for the user's model

do not mark the step complete or begin the next step.

## Server changes

Use two-byte payloads `[type, leave_seq]` for both `$56 LEAVE_ROOM` and `$57
LEAVE_ACK`. The sequence identifies retries within one connection; server
identity still comes only from the accepted socket.

1. Parse idempotent LEAVE_ROOM only from the sender's TCP connection. Release
   its seat immediately, but retain a bounded departing connection object until
   LEAVE_ACK/partial TX drains or a short deadline expires. Current `drop_client`
   closes and clears the socket immediately, so separate transport lifetime
   from reusable seat state. Bound departing fds and never attribute an old
   leave retry to the next occupant of that seat.
2. Treat duplicate LEAVE_ROOM and EOF following LEAVE_ROOM as the same completed
   departure.
3. Preserve current timeout/EOF behavior for unexpected loss. Replace the
   departed human with a configured Zombie immediately, with score/transients
   reset under the existing handoff contract.
4. When human count becomes zero unexpectedly, set
   `no_human_deadline_ms=now+grace`; preserve the round, bricks, remaining
   actors, and Zombie simulation.
5. Cancel the deadline when any human joins. The new human receives a fresh
   seat/score; no authenticated score restoration is added.
6. On expiry, reset the room to clean dormant/new-round state. Startup with no
   humans and voluntary departure of the final human also enter clean DORMANT
   immediately. Unexpected-loss grace starts when disconnect/timeout is
   detected, not at an unknowable physical unplug instant. Zombie-only round
   transitions cannot extend that original deadline. The current `zombie_ai`
   targets humans only: do not add Zombie-versus-Zombie combat to manufacture
   a grace-period victory. Resolve a victory internally if existing pending
   combat actually produces one, without a presentation delay.
7. Keep grace orthogonal to round state and cover ROUND_OVER/disconnect
   combinations explicitly.

## Client changes

1. Add LEAVING state. Stop gameplay input/TX, send LEAVE_ROOM, continue receive
   and ACK service for at most 0.5–1 second, then call `NET_ENDC` whether ACKed
   or timed out.
2. Linux clients expose equivalent clean leave behavior for deterministic
   tests.
3. Implement shared `NET_SESSION_RESET` now, derived from `NET_STATE_CLEAR` and
   actor/render initialization. Clear partial frames/TX, ACKs/revisions, pending
   inputs/replay, snapshots/maps/readiness, actors/shots/respawns, names/roles,
   watchdogs, round and display gates; preserve username, configuration, and
   validated selection. Use this path on leave, failed join, and reconnect.
   Round-only reset from 08-03 remains distinct and preserves the session.
4. Audit the actual firmware close requirement. Handler
   `NS_EndConcurrent_Impl` stops serial IRQs and deasserts motor; it does not
   issue a network close command. Verify supported FujiNet close/reopen behavior
   and implement the necessary ordinary SIO cleanup after `NS_END`. Establish
   a menu-safe VBI before ordinary SIO or `NS_INIT` uses `$82/$83`; SEI alone
   does not block VBI/NMI. Track partial initialization so failures clean up too.

## Verification

- Voluntary leave changes occupancy immediately and never starts grace.
- Unexpected final-human loss preserves room for 60 seconds; reconnect cancels
  expiry; expiry resets it.
- Old/unreachable server cannot trap a client in LEAVING.
- Duplicate leave and close races are harmless.
- A player joining a vacant seat receives a collision-safe spawn rather than
  reusing coordinates another actor may now occupy. Existing clients receive a
  final `RESPAWN` and redraw the joining sprite before that player moves.
- Physical Atari confirms bounded leave and clean NetStream shutdown.
- Verify actual server EOF/occupancy, not just `NET_ACTIVE=0`, and immediately
  reconnect to the same and a different server without rebooting FujiNet.
