## Changes

1. With NetStream stopped, query the configured QA `/view` endpoint through
   ordinary FujiNet network-device HTTP using `bin=1`, Atari platform,
   registered Maze War appkey, bounded page size, and offset. The current XEX
   embeds NetStream, not proof of a resident N: CIO handler: prefer small direct
   SIO wrappers, or explicitly package/measure a handler before relying on CIO.
2. Parse the three-byte header and one 189-byte record at a time. Pin field
   offsets in one table and reject truncated/oversized/schema-inconsistent
   responses.
3. Reuse inactive NetStream/gameplay buffers for the record buffer only under
   explicit state/lifetime aliases checked by assembly assertions.
4. Retain only compact display data and the selected validated URL needed for
   visible rooms; do not allocate a full multi-record response in Atari RAM.
5. Filter/validate game type, online status, exact public host, TCP scheme, and
   configured port range even though the server query is filtered.
6. Render room name and human occupancy in `HOSTSCR`. Support selection,
   refresh, empty/error states, OPTION Direct Connect, and optional change-name.
7. Write a newly selected public URL only to Maze War AppKey `$3022/$03/key
   $01`; read the official Lobby's `$0001/$01` launch key only as a fallback.
   after full validation.
8. Bound total bytes, page count, record count, per-read wait, and total request
   time. Handle partial reads and cleanly close the HTTP channel on error or
   cancel. Keep the visible menu rows and selection separate from the reusable
   record scratch; prove contiguity and the VBI-safe lifetime from 08-01.
9. If persisting a valid choice fails, show a brief not-saved message and allow
   joining it for this session. Use 08-07's common URL validator and AppKey
   writer, not a second parser with different host/port rules.
