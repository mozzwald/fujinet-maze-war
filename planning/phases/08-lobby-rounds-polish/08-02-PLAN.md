# 08-02 — Encapsulate one room, then add multiple TCP listeners

## Model and handoff

Use **`gpt-5.6-sol` with high reasoning**. Cross-cutting room ownership, connection lifetimes, and scheduling fairness need careful review.
Follow [08-MODELS.md](08-MODELS.md) for escalation, testing-based commit
approval, and handoff rules.

After required acceptance, recommend **08-03: `gpt-6-astra`, high
reasoning** for cross-client round/reset synchronization. Include this in the
user-facing closing summary and saved summary, then pause for the user's model
switch. If a test/approval gate is pending, say the recommendation is conditional;
do not mark the step complete or begin the next step.

## Goal

Turn the single-room server into isolated `Room` instances without changing
gameplay semantics.

## Changes

1. Introduce `struct room_config` and `struct room`.
2. Move into each room: listener fd/port, four clients, players, shots, brick
   map and canonical reset copy, input timestamps, packet sequence, broadcast
   timers, reliable queues, compatibility echo state, tick deadline, and all
   future round/grace fields.
3. Convert helpers to take `struct room *` where state belongs together. Keep
   pure packet/geometry helpers explicit and testable.
4. First run exactly one room and prove behavior parity.
5. Add `--room-count`, `--port-base`, per-room Zombie configuration, and
   validated limits. Preserve `--port` as a one-room compatibility option or
   reject ambiguous combinations clearly.
6. Build one nonblocking TCP listener per room and one poll table containing
   all listeners/clients. Listener identity selects the room.
7. Ensure every accepted fd, disconnect, reliable revision, brick update,
   snapshot, shot, name, and seat update is scoped to its room.
8. Add startup/shutdown cleanup for all listeners and clients.
9. Bound accepts/reads/writes per poll iteration and service every due room
   tick fairly. Preserve fixed deadlines with bounded overrun recovery. Keep
   partial-write buffers per connection and avoid a stale poll entry operating
   on a newly reused fd. Allocate the configured room collection with checked
   sizes rather than placing an unbounded collection on the stack.
10. Pin compatibility defaults (port 9000, Zombie configuration, tick rate,
    brick source) and reject conflicting port flags, overflow, duplicate ports,
    invalid room counts, or partial-listener startup failures cleanly.

## Verification

- One-room regression suite before enabling the second listener.
- Two simultaneous rooms with separate clients, bricks, scores, names, Zombie
  masks, packet sequences, and disconnects.
- Deliberately destroy the same coordinate in only one room and assert no
  packet/state change in the other.
- Run sanitizers on the server test build where available.
- Stall/flood a client in room 1 and prove room 2 ticks and delivery continue
  within the existing timing budget. Test rapid disconnect/accept fd reuse.

## Acceptance

At least two TCP rooms run in one process with no state leakage, while the
one-room command remains behaviorally compatible.
