# 08-10 — Session reset, repeated room switching, and QA launch

## Model and handoff

Use **`gpt-6-astra` with high reasoning**. Repeated switching exposes cross-system faults in firmware, interrupts, buffers, and external boot state.
Follow [08-MODELS.md](08-MODELS.md) for escalation, testing-based commit
approval, and handoff rules.

After required acceptance, recommend **08-11: `gpt-5.6-terra`, medium
reasoning** for release verification against an established checklist. Include this in the
user-facing closing summary and saved summary, then pause for the user's model
switch. If a test/approval gate is pending, say the recommendation is conditional;
do not mark the step complete or begin the next step.

## Changes

1. Audit/integrate the `NET_SESSION_RESET` introduced in 08-05. Verify it clears
   COBS/frame state, partial RX/TX,
   packet/reliable revisions, ACKs, pending inputs, replay, snapshots, shots,
   respawns, bricks/readiness, names, seat/role masks, local PID, watchdogs,
   movement/render reconciliation, round state, and display gates. Preserve only
   username, build configuration, and menu selection.
2. Implement the bounded route:
   `PLAYING/RESULTS -> LEAVING -> LEAVE_ACK|timeout -> NET_ENDC -> reset -> ROOM_MENU`.
3. Selecting any room, including the same room, uses:
   `reset -> install validated host/port -> NET_INIT -> JOINING`.
4. JOINING keeps the maze hidden until local PID/seat/role, BRICK_FULL, and a
   valid fresh snapshot are ready. If the room is in intermission, follow the
   round gate from 08-03.
5. A failed join always calls `NET_ENDC`, resets again, and returns to a readable
   menu. It cannot recurse through `RESTART` or strand the stack.
6. Verify external QA Lobby launch: username and selected URL AppKeys route
   directly to the chosen room; switching updates the last-room key; reboot
   rejoins the new selection.
7. Resolve the actual external Lobby boot artifact before QA launch: the build
   currently produces an XEX, while the supported public loader may need a
   bootable disk/container. Package and test the complete NetStream + game
   load path and memory map; a downloadable XEX alone is not boot proof.

## Verification

- Automate at least 20 switches: room 1->2, 2->1, 1->1, valid->unavailable,
  full room, server disappears after refresh, and Lobby outage->Direct Connect.
- Assert no old room names, actors, bricks, shots, scores, reliable revisions,
  or round state survive.
- Observe both old and new servers: old receives leave/close and updates human
  occupancy; new performs a fresh handshake.
- Run the complete external QA Lobby boot/select/switch/reboot flow.
- Observe stack depth/sentinels, menu VBI ownership, serial IRQ restoration,
  POKEY guards, real firmware/server close, and failed partial initialization
  across the full switch sequence. Recover without recursively entering START.

## Hardware checkpoint

Repeat switching on physical Atari/FujiNet and watch for black screens, SIO
lockups, stale bytes, handler restart failure, wrong-room state, VBI/input loss,
or a required FujiNet reboot. Stop until repeated hardware switching is solid.
