# 08-07 — AppKeys, URL validation, and startup routing

## Model and handoff

Use **`gpt-5.6-sol` with high reasoning**. Direct SIO and persistent selection combine strict buffer bounds with connection-state recovery.
Follow [08-MODELS.md](08-MODELS.md) for escalation, testing-based commit
approval, and handoff rules.

After required acceptance, recommend **08-08: `gpt-5.6-terra`, medium
reasoning** for an isolated asynchronous publisher with a defined contract. Include this in the
user-facing closing summary and saved summary, then pause for the user's model
switch. If a test/approval gate is pending, say the recommendation is conditional;
do not mark the step complete or begin the next step.

## Changes

1. Add small direct-SIO AppKey wrappers for creator `$0001`, app `$01`, using
   username key `$00` and the registered/configured Maze War game key. Preserve
   the count returned by firmware and always terminate buffers within bounds.
2. Read the Lobby username first. Accept 1–8 valid display characters after
   the same sanitization used by the server; otherwise use manual name entry.
3. Budget the direct-SIO response separately from its string: default AppKey
   reads include a two-byte returned length plus up to 64 payload bytes, with
   an additional local terminator if needed (67 bytes total scratch). Pin the
   firmware mode and reject impossible counts before indexing/copying. A plain
   64-byte destination is insufficient. Read the selected room URL and validate
   exact `tcp://host:port` syntax: complete parse, configured public host,
   configured contiguous port range, no path/query/fragment, no overflow.
4. A valid username plus valid selected room may autojoin. Missing/invalid data
   enters the room menu/title route. A failed connection preserves the stored
   URL and returns safely.
5. Changing the public username writes the shared Lobby username key. Manual
   Direct Connect never writes the public selected-room key.
6. Document AppKey size, buffer ownership, QA appkey policy, and production
   registration dependency.
7. Holding OPTION at startup bypasses autojoin and enters setup/menu, including
   when the stored server is reachable. Debounce console input and avoid an
   endless autojoin/error loop. A failed AppKey write reports that the choice
   was not saved but still permits the validated connection for this session.

## State and memory

AppKey SIO runs only with NetStream stopped. Alias temporary AppKey/URL parse
storage with inactive network buffers where lifetime analysis proves safety;
copy only the validated host and numeric port into persistent connection
configuration protected from `NET_SESSION_RESET`. Use the lifecycle established
in 08-05, and make all SIO error paths restore DCB/OS state and menu operation.

## Verification

Test present, absent, empty, unterminated, too-long, invalid-character, wrong
scheme, wrong host, out-of-range port, suffix/path, unavailable server, SD-card
failure, QA build, and LAN build cases.

Physical FujiNet with SD storage and a no-usable-AppKey fallback checkpoint are
required.
