## Protocol

Reserve:

- `$54 MATCH_END`, server to client, reliable-event inner payload;
- `$55 ROUND_START`, server to client, reliable-event inner payload;
- `$56 LEAVE_ROOM`, client to server;
- `$57 LEAVE_ACK`, server to client.

Implement the versioning, round identity, liveness, queue bounds, and reset
barrier in [08-PROTOCOL.md](08-PROTOCOL.md). Freeze the wire-layout fixtures
first, including all three clients and test tools. Proposed inner payloads:

```
MATCH_END (43 bytes)
[0]      $54
[1]      round_id
[2]      winner_pid
[3]      final_active_mask
[4]      final_zombie_mask
[5]      kill_limit
[6..9]   final scores p0..p3
[10]     historical_zombie_mask
[11..42] four frozen 8-byte display names

ROUND_START (3 bytes)
[0]      $55
[1]      round_id
[2]      kill_limit
```

The server freezes normalized result names, using slot-qualified `WIZARD n` or
`ZOMBIE n` fallback text where needed. This makes late-join/intermission results
self-contained and prevents subsequent NAME/seat handoff from rewriting them.
Expand `RELIABLE_EVENT_MAX` and Atari `REL_PKT_MAX` for both this event and the
larger round-tagged reliable full-map baseline. MATCH_END plus wrapper and CRC
is 49 decoded bytes. Prove every encoded and decoded frame fits, and decouple
the current exact NAME length check from `REL_PKT_MAX`.
All messages retain existing COBS+CRC framing.

## Server changes

1. Add room round state, modulo-256 `round_id`, validated `kill_limit` 1..10,
   intermission deadline, final occupancy/roles, historical Zombie mask, and
   frozen result data. Do not infer winner role from historical slot ownership.
2. Detect the first score reaching the limit at the scoring mutation itself,
   clamp it, stop later same-tick combat, and enter `ROUND_OVER` once.
3. Enqueue one reliable MATCH_END per client. Duplicates/retransmissions carry
   identical frozen data.
4. Continue frozen snapshots and accept neutral heartbeats during intermission,
   but suppress gameplay mutation in both ingress and simulation paths.
5. On deadline, restore the canonical bricks, zero scores, retire shots and
   echoes, reset respawns/input/transients, assign valid spawns, increment
   round ID, and initiate the reliable authorization/map/snapshot barrier in
   `08-PROTOCOL.md`. Do not assume enqueue order is wire delivery order.
6. Define joins during ROUND_OVER: give seat metadata/name state, send the
   frozen round state needed for a coherent wait screen, and do not admit
   gameplay until reset.

## Client changes

1. Decode the two new server events in the reliable-event dispatcher on Atari
   and both Linux clients.
2. Compare round IDs with explicit duplicate/stale/wrap handling; bind every
   round-scoped input, snapshot, map, event, and echo to its epoch.
3. Cache MATCH_END atomically and gate normal input/action processing.
4. Do not leave results because BRICK_FULL arrived. Require matching
   ROUND_START plus completed map and fresh snapshot readiness.
5. Reset per-round client transients without resetting the TCP session or
   reliable revisions. Add a minimal synchronized wait/results display in all
   clients now; optional effects belong to 08-04.
6. Measure the added round fields and baseline/retry traffic against the
   Phase 6 movement baseline, especially on the 57600-baud Atari link. Avoid
   redundant per-tick control packets and unbounded baseline retransmission.
