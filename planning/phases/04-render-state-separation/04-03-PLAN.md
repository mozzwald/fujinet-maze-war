# 04-03 — Interpolate remote actors through render state

## Acceptance update — 2026-09-10

The user reports persistent remote lag and jumpiness on hardware/emulation and
emulation/emulation. Smoothness acceptance failed; this work is reopened.
See [04-LAG-REVIEW.md](04-LAG-REVIEW.md) for confirmed animation/recovery defects,
real-server TCP timing results, and the staged repair plan. Earlier implementation
and successful smoke checks below do not establish smoothness or timing correctness.

## Why

`REMOTE_FOLLOW` already walks remote slots toward their authoritative cells
using the normal move animation, which is the right instinct, but it does so by
moving their *simulation* position and it hard-snaps as a guard rail
(`CKMVAP`). With render state available from `04-02`, remote motion becomes
presentation: the authoritative cell is set immediately, and the render
position interpolates toward it.

This is also what makes RNDR-02 checkable rather than asserted — remote actors
are visibly smooth *and* provably not predicted.

## Shape

Point `REMOTE_FOLLOW` at the render position. Keep the authoritative cell as the
single truth for occupancy and shot interaction. The existing desync counter and
hard-snap guard rail stay, but act on render state.

## Watch out for

- Zombies are server actors with the same representation as humans; they must
  come through the same path, not a special case.
- Do not smooth a respawn or a join. Those are legitimate discontinuities; a
  slide across the maze is worse than a jump. `NET_GLIDE_MAX` already encodes a
  distance beyond which walking is wrong — reuse that judgement.

## Done when

- Remote wizards and zombies read as smooth in a mixed session, judged by the
  user on real hardware.
- The guard test shows no remote smoothing value reaching a gameplay site.
- Phase 4 success criteria 1-3 in ROADMAP.md are all demonstrably true, which
  closes RNDR-01 and RNDR-02 and unblocks Phase 6.

## Result

Implemented 2026-09-10. Remote actors now keep authoritative simulation truth
in `LOCX/LOCY` immediately when a staged snapshot commits, while
`REMOTE_FOLLOW` walks only `RNDX/RNDY` toward that authoritative cell. Every
remote follow step marks `NET_RCHASE_STEP` before entering `INITMOVE`, so the
normal animation path moves the picture without advancing simulation a second
time. Path checks use `NET_AHEAD_FREE_RND`, so the render walk still avoids
erasing bricks while keeping collision and shot origin on simulation state.

Final respawns now call `NET_AUTH_REPOS` and `SETSTIL`, because respawn/join is
a real discontinuity and should not slide across the maze as if it were network
drift.

Validation:

- `make build/maze-war-net.xex`
- `bash tests/render_state_separation_smoke.sh`
- `bash tests/respawn_echo_smoke.sh && bash tests/death_render_smoke.sh`

complete, but whether the remote actor motion feels better must still be judged
