# 04-07 Plan - Mark HUD Rows With Player Shirt Colors

## Goal

Make each bottom-of-screen player row identify the matching sprite shirt color
without reintroducing the DLI flicker seen during hardware/emulator testing.

## Implementation update - 2026-09-10

Initial implementation proved that exact per-slot HUD name text colors require a
vertical color split: mode 6 text chooses among `COLPF0..COLPF3`, and without a
DLI the maze and bottom HUD share those same registers. Enabling the DLI made
the name colors match the shirt colors, but hardware/emulator testing reported
constant flicker and startup HUD character corruption.

The follow-up implementation keeps gameplay DLI disabled (`NMIEN=$40`) and uses
four missile PMGs as small shirt-color swatches beside the four HUD name rows.
The actor sprites already consume the four player PMGs, but the missile page was
unused after Phase 04-04 disabled accidental missile DMA. Phase 04-07 now makes
that missile use intentional: `HUD_PM_INIT` positions all four missiles, sets a
visible width, clears `PMAREA+$300`, writes six scanlines per HUD row, and only
then enables `GRACTL=$03` when the game display first becomes visible. Startup
and reconnect prompts keep `GRACTL=$02`, so the swatches do not appear over the
host/connect screens.

The HUD text itself now uses one stable blue non-DLI color through
`NAMECOL .BYTE $40,$40,$40,$40`, while the missile swatches carry the shirt
color identity. `START` explicitly blanks all four stored-name slots to spaces,
because `NET_NAMES` sits after `NET_INIT_ARGS` and is intentionally outside
`NET_STATE_CLEAR`'s zeroed block. Fallback `WIZARD`/`ZOMBIE` labels now use
clean ATASCII source bytes and pass through the same `NAME_SCR` plus `NAMECOL,X`
path as player-entered names, which removes the old pre-colored label variants
that showed up as semicolon-like zombie text.

`tests/hud_name_color_smoke.sh` pins the no-DLI map-sync path, all-blue HUD text,
the shared label rendering path, clean fallback label bytes, and the missile
row/bit tables. `tests/player_names_smoke.sh` pins the startup stored-name clear.
`tests/pm_init_smoke.sh` now allows missile DMA only when it is immediately
preceded by `HUD_PM_INIT`, while still guarding the original real-hardware PM
memory clear ordering.

## Source Findings

Exact text coloring is possible with the current display-list/DLI design, but
the user-tested DLI path flickers badly. The PMG marker alternative is possible
with the current player/missile layout:

- Player PMGs 0..3 are already used for actors.
- Missile PMGs 0..3 were unused and were previously disabled after the
  real-hardware uninitialized missile artifact.
- With fifth-player mode clear, each missile uses the matching player color:
  missile 0 is player 0 green, missile 1 is player 1 blue, missile 2 is player 2
  pink, and missile 3 is player 3 yellow.
- The marker bytes live in the missile quarter at `PMAREA+$300`.
- `NET_NAME_DRAW` and the fallback label path still centralize text color through
  `NAMECOL,X`, but the color identity now comes from the PMG marker.

The stable no-DLI text table is:

```asm
NAMECOL .BYTE $40,$40,$40,$40
```

Every label uses the same blue text color. The shirt color is shown by the PMG
missile marker, so no slot needs to use `$80`, the black maze playfield band.

## Scope

- Keep player-entered names drawn by `NET_NAME_DRAW` readable with DLI off.
- Show a shirt-color marker beside each HUD row with initialized missile PMGs.
- Keep zombie labels readable and intentional by routing them through the same
  screen-code/color-band path as entered names.
- Decide whether score digits should stay as-is or match the player name color.
  The user request is for names, so score digits are optional and should not
  block the phase.

## Implementation Plan

1. Add or update a smoke test that proves gameplay keeps DLI off and that
   `NET_NAME_DRAW` applies the stable `NAMECOL` table to every displayed name
   character.
2. Add `HUD_PM_INIT` to position, size, clear, and draw the four missile marker
   rows.
3. Enable missile DMA only after `HUD_PM_INIT` and only when the game display is
   first shown.
4. Route fallback `WIZARD`/`ZOMBIE` labels through the shared per-slot text path.
5. Build `build/maze-war.xex` and run the HUD/name and PM init smoke coverage.
6. Optional visual check: boot an emulator session with names in all four slots
   and confirm the HUD names line up with the sprite shirt colors.

## Acceptance

- A named human in each slot has a HUD row marker using that slot's shirt color.
- Gameplay leaves the DLI off to avoid the reported flicker.
- The change does not alter gameplay state, packet handling, score values, or
  actor colors.
- Existing embedded-font and name-display tests still pass.
